# Classical TDOA baselines

Use **SCO, SUM and GTRS** from the official DeviceIoT archive with their released parameters, weighting steps and root selection. The project adapter returns one column per estimator in that order. It records native outputs, exceptions and the last MATLAB warning for each call. [Adapter](matlab/device_iot/device_iot_estimates.m) · [Version, hashes and citation](SOURCES.md)

The MATLAB interface takes absolute station coordinates in m (3×7), six range differences in m relative to column 1, dense Qr in m² (6×6) and full station-major Qs in m² (21×21). All three functions internally form relative station coordinates. Their native MPR angles and signed inverse range refer to the reported reference receiver. Its position is exactly the global origin in the two selected sweeps, so native and global MPR coincide. Cartesian output is also saved directly from each original function. [Geometry and plotting protocol](../paper/EXPERIMENT_CONTRACT.md) · [Run instructions](../experiments/README.md)

The fourth column is the Chan–Ho Cartesian estimator distributed by CISP. It uses the same station positions, six range differences and dense Qr, and assumes known stations. Its adapter saves the absolute native position and converts the displacement from the reference station into azimuth, elevation and reciprocal Euclidean range for scoring. A position at the reference has undefined direction and inverse range. [Cartesian adapter](matlab/chan_ho1994/chan_ho_estimate.m) · [Official source](https://cisp.ece.missouri.edu/code/TDOALoc/TDOALoc.zip)
